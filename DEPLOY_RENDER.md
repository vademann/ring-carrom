# Бесплатный тестовый сервер Render

Статус на 18.10.2026: работает `https://ring-carrom-relay.onrender.com`, APK использует `wss://ring-carrom-relay.onrender.com/ws`. Проверены health/config, поиск, сообщения, приглашение, настоящая партия APK/браузер и фоновая доставка заявки через Firebase.

## Публикация

1. Создать аккаунт https://dashboard.render.com/register и подключить интеграцию Render в Codex. Секреты в чат не отправлять.
2. `python package-cloud.py` создаёт `deploy/ring-carrom-render.zip`: только актуальный сервер и игровые assets. В архиве нет SQLite, старых социальных данных, секретов установок, журналов, локальных настроек или APK.
3. Распаковать архив в корень отдельного GitHub/GitLab репозитория и предоставить Render доступ к нему. Существующий локальный сервер и базы не переносить автоматически.
4. В Render создать Blueprint из этого репозитория (`render.yaml`), проверить **Free**, один Web Service, без дисков и баз. Или создать Python Web Service вручную: Frankfurt, build `pip install -r requirements.txt`, start `python -u server.py`, health `/health`, plan Free. Один процесс/экземпляр: комнаты и пересылка находятся в RAM.
5. Render задаёт `PORT` и `RENDER_EXTERNAL_URL`. Сервер слушает `0.0.0.0:$PORT`; `/config` возвращает его постоянный WSS-адрес. TLS и WebSocket обслуживает платформа. Браузерная игра доступна на корневом HTTPS-адресе.
6. После успешного deploy проверить `/health`, `/config`, два независимых клиента, заявки, переписку и матч. Затем выполнить `./use-cloud-server.ps1 -ServerUrl https://ИМЯ.onrender.com`. Скрипт проверяет сервис и пересобирает APK с его точным адресом; при ошибке сборки восстанавливает прежнюю конфигурацию.

Нативный Android-мост доверяет точным HTTPS-хостам, встроенным в `server-config.js` APK. Общий доступ ко всем доменам Render не разрешается. Debug HTTP-исключение для эмулятора сохранено; в release HTTP не добавлялся.

## Ограничения бесплатного тарифа

Render усыпляет сервис после 15 минут без входящих HTTP/WebSocket сообщений. Пробуждение занимает примерно минуту, поэтому первое подключение может потребовать повторной попытки. Включены 750 часов в месяц на workspace, также действуют квоты трафика и сборок. Не включать платные тарифы/автоматическую оплату превышения; при исчерпании квоты сервис может остановиться. Актуальные условия: https://render.com/docs/free и https://render.com/docs/websocket .

Друзья, заявки, переписка и очередь остаются на телефонах. Перезапуск облачного процесса завершает текущие комнаты, теряет маршруты и транзит; устройства снова регистрируются и повторяют неподтверждённую доставку.

Версия 2.0 сохраняет рейтинг и последние матчи в Firestore (`rc_career`, `rc_match_receipts`), SQLite используется как локальный кеш. Для переноса прежнего рейтинга до замены старого сервера сохраните его `career.sqlite3`. `python migrate_career.py --database PATH` проверяет источник; `--apply` переносит отсутствующие профили без перезаписи существующих облачных данных. Сам по себе архив исходников старую базу не содержит. Если прежняя база уже потеряна, восстановить её рейтинг по одному локальному профилю нельзя.

Архив является исходниками для Git-репозитория, не прямым ZIP-deploy: Render собирает код из репозитория.

## Firebase push

Проект `ring-carrom`; Firestore `(default)` хранит `rc_push_routes/{publicId}` с полями `token` и `updated`, а с версии 2.0 также серверный рейтинг/историю матчей и квитанции результатов. Клиентские правила запрещают доступ; сервер использует Admin credentials через google-auth. FCM временно очередит события; списки друзей и переписка в Firestore не записываются.

Сервисный ключ размещается как Render Secret File; переменная `GOOGLE_APPLICATION_CREDENTIALS` указывает путь этого файла (например `/etc/secrets/firebase-admin.json`). Для локальной разработки поддержан `secrets/firebase-admin.json`. Ключ не включать в репозиторий, архив или APK. Включить Firestore API и FCM HTTP v1 API; учётной записи нужны права на документы Firestore и отправку FCM. Действующее подключение проверено реальной доставкой.

Android-конфигурация: `app/google-services.json`, пакет `com.example.ringcarromv1`. После сборки пользователь включает уведомления в настройках игры и разрешает их в Android. Бонус планируется локально. Подробный отчёт: `../Ringcarromv1/NOTIFICATIONS_QA.md`.

## Обновление 2.0

Архив подготовлен и проверен локально; новый сервер ещё не опубликован в Render. Дополнительная зависимость `mini-racer==0.14.1` содержит V8 для расчёта ударов; Node.js не требуется. Build/start команды остаются прежними. Сохранить существующий Firebase Secret File. Доступ к Firestore проверен реальной атомарной записью и удалением только тестовых записей.

После deploy `/health` должен содержать `version: "2.0"`, `authoritativePhysics: true`, `cloudCareer: true`. Проверить `/.well-known/assetlinks.json`: в нём указан сертификат текущего debug APK; для другой подписи добавить её SHA-256. Провести матч двух клиентов и проверить награду/историю после перезапуска. Полный отчёт и ограничения — `../Ringcarromv1/UPDATE_2_0.md`.
